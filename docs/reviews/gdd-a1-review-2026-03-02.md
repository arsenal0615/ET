## Critical Issues (必须修复)

### C1. 断线重连行为未定义 (技术+QA)
- **来源:** 技术评审 [C2] + QA评审 [Critical-01]
- **问题:** 断线重连被列为 Phase 2，但 4 人在线局中任意玩家断线的状态机行为完全未定义（暂停？AI 接管？弃局？）。无法设计网络异常测试用例。
- **建议:** MVP 至少定义"断线超时认输 + 其他玩家继续 + 状态快照保留"兜底方案。

### C2. 哥布林白嫖单位的卡池守恒豁免未说明 (策略+QA)
- **来源:** 策略评审 [I4] + QA评审 [Critical-03]
- **问题:** 白嫖单位"不扣卡池"，但出售/淘汰时是否回流卡池？若回流则守恒被破坏，若不回流需要 `isGoblinGift` 标记。
- **建议:** 明确规则：白嫖单位出售/淘汰不回流卡池（需标记），或改为从卡池抽取。

### C3. 战斗模拟器"单端跑还是双端跑"未明确 (技术)
- **来源:** 技术评审 [C1]
- **问题:** .NET 8 (服务端) 与 HybridCLR/IL2CPP (客户端) 的浮点运算可能有差异。若战斗模拟仅服务端执行则无碍，若客户端需重跑（回放/验证），必须上定点数。
- **建议:** 在 GDD 中明确："战斗模拟仅服务端执行，客户端只播放事件流"。

### C4. PRNG hash 函数未规范 (QA)
- **来源:** QA评审 [Critical-04]
- **问题:** `hash(matchSeed, round, purpose)` 中 purpose 的取值枚举和 hash 函数实现均未指定。不同程序员各自实现会导致不同模块 PRNG 输出相互干扰，且金标测试可能因实现差异而失败。
- **建议:** 在详细设计中统一指定 hash 函数（如 xxHash）和 purpose 枚举。

### C5. 战斗阶段购买与板凳/合成/扣血的交互规则空白 (QA)
- **来源:** QA评审 [Critical-02]
- **问题:** 战斗阶段可购买进板凳，但板凳已满时的行为、购买单位是否影响扣血公式等未明确定义。
- **建议:** 补充：战斗阶段 BUY + 板凳满 = BENCH_FULL；战斗中购买的单位不参与当回合扣血计算。

### C6. 经济策略路线单一化 (策略)
- **来源:** 策略评审 [C1]
- **问题:** 仅"省钱/赌狗"两条路线，缺乏第三条策略路线。+4/回合固定收入 + 仅败者被动 = 经济分叉极少。
- **建议:** 明确哥布林羁绊是否是刻意设计的唯一经济差异化路线，在文档中声明设计意图。

### C7. 4★可达性预期未对齐 (策略)
- **来源:** 策略评审 [C2]
- **问题:** 合成4★需消耗8份相同单位，在12回合内的可达性是概率事件还是策略事件？GDD 未明确出货概率表。
- **建议:** 补充出货概率表，明确4★在单局内的期望出现频率。
