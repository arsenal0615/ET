## 1. Game Overview

### 1.1 Vision Statement

A1 是一款 4 人在线自走棋，以"快节奏构筑 + 共享卡池博弈 + 站位决定命运"为核心，单局 5-8 分钟，强调低操作高策略、强复盘可解释。

### 1.2 Target Audience

喜欢自走棋/卡牌构筑但嫌传统自走棋太长、操作太复杂的手游玩家。碎片时间友好。

### 1.3 Reference Games & Differentiation

| 参考 | 借鉴 | A1 差异 |
|------|------|---------|
| Clash Royale: Merge Tactics | 单位卡池、羁绊、自动战斗 | 独立设计，非 IP 衍生 |
| 自走棋 (TFT/DAC) | 共享卡池、构筑+站位 | 2合1（非3合1）、4人局、5-8分钟极短单局 |
| 皇室战争 | 圣水经济、单位原型 | 回合制自走棋，非实时对抗 |

### 1.4 Core Pillars

1. **快节奏** — 20秒决策、5-8分钟单局、8-12回合收敛
2. **低操作高策略** — 操作门槛低，赢在构筑选择/资源管理/站位克制
3. **强复盘可解释** — 输赢能说清楚（羁绊触发/合成星级/站位被克）
4. **同池博弈** — 共享卡池制造玩家间隐性对抗（省钱/赌狗/转型/卡别人）

## 2. Core Gameplay

### 2.1 Core Loop

```
匹配入局 → [回合循环] → 淘汰/胜利
                ↓
    回合开始(2s): 发钱+分配对手
         ↓
    部署阶段(20s): 买/卖/合/摆
         ↓
    准备对战(3s): 锁定+校验
         ↓
    自动战斗(30s): 服务端模拟，客户端播放事件流
         ↓
    回合结算(3s): 败者扣血，淘汰判定
         ↓
    → 下一回合 / 游戏结束
```

### 2.2 Primary Mechanics

玩家核心动词：
- **购买** — 从商店花圣水买单位
- **出售** — 卖单位回收圣水（cost-1，交易摩擦）
- **合成** — 2个同兵种同星级自动合并升星
- **摆位** — 在8×5六边形棋盘上放置/调整站位
- **观察** — 战斗阶段观看自动战斗、观察对手阵容

### 2.3 Player Controls & Interactions

操作分阶段限制：

| 操作 | 部署阶段 | 战斗阶段 |
|------|---------|---------|
| 购买 | 可 | 可，但只进板凳 |
| 出售 | 可（棋盘+板凳） | 仅板凳单位 |
| 合成 | 自动触发 | 不触发（延后到下次部署） |
| 摆位/换位 | 可 | 禁止 |

### 2.4 Game Feel & Feedback

- 战斗全自动——玩家决策的反馈延迟到战斗阶段集中呈现
- 每回合20秒决策压力制造紧张感
- 合成升星瞬间有"2合1"的视觉冲击（倍率翻倍）
- 战报事件流确保战斗可回放、可解释
- Frenzy Time 金色高亮 + 攻速翻倍 → 终局加速的紧迫感

## 3. Game Systems

### 3.1 经济系统（圣水 Elixir）

**Purpose:** 控制构筑节奏，制造"省钱 vs 赌狗"的决策张力

**Mechanics:**

| 来源 | 数量 |
|------|------|
| 回合基础收入 | +4/回合 |
| 统帅被动（战败后） | +randInt(4,8) |
| 出售返还 | max(cost-1, 0)，与星级无关 |
| 合成返还 | +1/次合并（连锁各自返还） |

- 圣水上限: 999
- 购买后触发商店整行刷新

**Interactions:** 商店（购买消耗）、单位（出售/合成回流）、统帅（被动收入）

### 3.2 商店与共享卡池

**Purpose:** 提供构筑选择，通过共享卡池制造玩家间隐性对抗

**Mechanics:**

商店规则：
- 3 槽位，购买成功后整行重随（非单槽）
- 不主动刷新，无锁定机制
- 同屏 3 槽 templateId 不重复

共享卡池：
- 24 种模板 × 8 份拷贝 = 192 份总量
- 全玩家共享库存
- Offer 预扣机制：生成 offer 时立即预扣 1 份
- 出货概率：从剩余库存中等概率抽取

星级与拷贝数守恒: 1★=1, 2★=2, 3★=4, 4★=8
- 合成不改变库存总量
- 出售/淘汰按星级回流

**Interactions:** 经济（消耗圣水）、单位（生成实例）、回合结算（淘汰回收）

### 3.3 单位系统

**Purpose:** 提供构筑积木，通过合成升星创造成长感

**Mechanics:**

基础属性: hp, atk, atkSpeed, range(1/3), moveSpeed, critChance, critMultiplier(1.5), mana, tags(2个羁绊)

单位池: 24 种（7×2费 + 7×3费 + 6×4费 + 4×5费）

合成（2合1）:
- 1★+1★→2★, 2★+2★→3★, 3★+3★→4★
- 倍率: 1★×1, 2★×2, 3★×4, 4★×8（HP和伤害同倍率）
- 合成后满血，每次返还 1 圣水
- 确定性顺序: 低星先扫 → templateId → 棋盘优先板凳 → y→x→instId

棋盘: 8×5 六边形, 板凳容量 5, 人口上限 R1=2→R5+=6

**Interactions:** 商店（购买来源）、羁绊（标签统计）、战斗（作为战斗实体）

### 3.4 羁绊系统

**Purpose:** 构筑主线，引导玩家围绕标签组合阵容

**Mechanics:**
- 每单位 2 个标签，13 种羁绊
- 阈值: 2（level 1）/ 4（level 2），仅统计上场单位
- 效果仅作用于拥有该标签的单位
- PreBattle 生成 TraitSnapshot，战斗全程不变

13 种羁绊:

| 羁绊 | 定位 | 核心效果 |
|------|------|---------|
| 王牌 Ace | 单C养成 | 队长+伤害+吸血(40%/70%) |
| 刺客 Assassin | 切后排 | 开战跳后排+暴击(30%/60%) |
| 火力手 Blaster | 远程增伤 | 射程+1+距离增伤(10%/15%每格) |
| 斗士 Brawler | 肉盾 | 最大生命(+50%/+100%) |
| 追猎者 Brutalist | 持续输出 | 攻速(+30%/+60%)+印记削最大生命 |
| 部落 Clan | 爆发窗口 | 低血触发治疗+攻速(35%/70%)持续5秒 |
| 巨人 Giant | 外挂减伤 | 受伤-40%（仅1档） |
| 哥布林 Goblin | 经济 | 次回合白嫖哥布林单位（不扣卡池） |
| 皮卡 P.E.K.K.A | 滚雪球 | 击杀后回血60%+增伤40%（仅1档） |
| 贵族 Noble | 站位依赖 | 前排减伤/后排增伤(25%/40%) |
| 游侠 Ranger | 后期成长 | 攻击叠攻速(+10%/+15%每次，有上限) |
| 巨星 Superstar | 技能爆发 | 技能预充(1/3或2/3)+连发50%概率(最多4次) |
| 亡灵 Undead | 反肉 | 诅咒高血敌人削最大生命(25%/50%) |

**Interactions:** 单位（标签来源）、战斗（快照影响战斗数值）、哥布林经济→回合开始

### 3.5 技能系统（Cell 流水线）

**Purpose:** 赋予单位个性，创造战斗观赏性

**Mechanics:**

架构: SkillDef = TriggerCell + TargetCell + EffectCell[] + TimingCell? + ScalingCell?

触发器(6类): COMBAT_START / INTERVAL / ON_HIT_COUNT / ON_KILL / ON_HP_BELOW / MANA_FULL

法力条: 普攻+10, 受击+6, 满100释放

目标(9类): SELF / NEAREST / FARTHEST / LOWEST_HP / CLUSTER / AREA_RADIUS / LINE_PIERCE / CONE / MULTI_TARGETS

效果(10类): DAMAGE / HEAL / STUN / KNOCKBACK / INVISIBILITY / SUMMON / SPAWN_ON_KILL / CLONE_SELF / REFLECT / ROCKET

24 单位 → 16 个 SkillDef 模板，通过 ScalingCell 绑定星级参数

**Interactions:** 战斗（技能在模拟中执行）、单位（星级影响技能参数）

### 3.6 战斗系统（确定性自动模拟）

**Purpose:** 将构筑决策转化为可观赏、可回放、可解释的战斗结果

**Mechanics:**

核心参数:
- Tick Rate: 20 ticks/s (dt=50ms)
- 最大时长: 600 ticks (30秒)
- 棋盘: 8×5 六边形 (odd-r offset)

每 Tick 顺序(固定):
1. 到期计划任务 → 2. 状态到期 → 3. 单位行动(instId升序) → 4. 死亡清理 → 5. Frenzy检测

目标选择: 射程内最近 → 仇恨优先 → instId升序

Frenzy Time(最后10秒): 攻速×2, 隐身时长×0.5

确定性: 全局固定种子 PRNG，子种子 `hash(matchSeed, round, purpose)` 派生

输出: CombatEvent[] 事件流（SPAWN/MOVE/ATTACK/DAMAGE/HEAL/CAST/BUFF/DEATH/ROUND_END）

**Interactions:** 技能（战斗中执行）、羁绊（快照影响数值）、回合结算（胜负结果）

### 3.7 统帅系统

**Purpose:** 玩家生命载体 + 经济偏好

**Mechanics:**

MVP 仅 1 位: 皇室国王
- 初始生命: 12
- 被动: 战败后 +randInt(4,8) 圣水

**Progression:** Phase 2 引入更多统帅，提供不同被动

### 3.8 回合结算

**Purpose:** 推动对局收敛，8-12 回合自然结束

**Mechanics:**

配对: Fisher-Yates 洗牌
- 4人→2场1v1, 3人→1v1+Ghost, 2人→固定对打
- Ghost = 最近淘汰者阵容快照，赢Ghost不扣血

扣血: 输家 = 对面剩余有效单位数 + 1（Skeleton/Clone 不计入）

平局: 超时或同归于尽 → 双方各扣 1

淘汰: hp≤0 出局，同回合多人淘汰按 hp/hpBefore/剩余单位/playerId 排名

**Interactions:** 战斗（胜负结果）、卡池（淘汰回收）、统帅（生命载体）

## 4. Content & Progression

### 4.1 Session Design

```
匹配(~5s) → 加载(~3s) → 8-12回合(每回合~58s) → 结算
总时长: 约 5-8 分钟
```

### 4.2 Content Matrix

| 内容 | 数量 |
|------|------|
| 单位模板 | 24（7×2费 + 7×3费 + 6×4费 + 4×5费） |
| 羁绊 | 13 种（各2档阈值） |
| 技能模板 | 16 个 SkillDef |
| 统帅 | 1（MVP） |

### 4.3 Difficulty Curve (单局内)

| 回合 | 节奏 | 体验 |
|------|------|------|
| R1-2 | 起步 | 拿赠送单位+低费卡，试探方向 |
| R3-4 | 成型 | 羁绊凑齐2阈值，出现2★ |
| R5-7 | 高潮 | 人口满6，3★/4★出现，4阈值触发 |
| R8+ | 收敛 | 玩家淘汰，Frenzy加速终局 |

### 4.4 Replayability

- 共享卡池 → 每局可用单位不同
- 随机商店 + 对手博弈 → 每局构筑路线不同
- 短单局 + 低操作 → 碎片时间友好，"再来一把"

## 5. Narrative Design

A1 叙事极轻量（竞技向自走棋常态）：

- **世界观:** 卡通奇幻风格
- **故事:** 无剧情线，纯竞技对战
- **角色:** 单位以经典卡牌游戏角色为原型，自带辨识度
- **叙事传达:** 通过单位造型、技能表现、羁绊命名传达角色个性
- **玩家代入:** 统帅 = 玩家化身

## 6. Technical Considerations

### 6.1 Server Authority Requirements

| 系统 | 权威级别 | 说明 |
|------|---------|------|
| 战斗模拟 | 强权威 | 确定性模拟在服务端执行，客户端只播事件流 |
| 经济/商店/卡池 | 强权威 | 涉及共享资源，必须服务端仲裁 |
| 合成/摆位校验 | 强权威 | 防作弊，服务端校验合法性 |
| 配对算法 | 强权威 | 服务端确定性配对 |
| UI/表现 | 客户端 | 按事件流播放，部署期乐观更新+回滚 |

### 6.2 Performance-Critical Systems

- 战斗模拟器: 20 ticks/s × ≤12单位 × 2场并行
- 六边形寻路: 每tick每单位一次，需轻量算法
- 事件流序列化/传输: 单场数百条事件

### 6.3 Data Persistence Needs

- 对局状态: 阶段切换时可做快照
- 配置表: 单位/技能/羁绊定义，需版本化
- 对局结果: 胜负/排名记录
- 重连: MVP 非必做

### 6.4 Network Synchronization

- 同步模型: 操作意图上行 + 事件流下行（非帧同步）
- 部署阶段: 提交操作意图，服务端校验后广播
- 战斗阶段: 完整 CombatEvent[] 一次性/流式下发

### 6.5 Determinism (核心技术约束)

- 全局禁止 Math.random()，必须固定种子 PRNG
- 子种子: hash(matchSeed, round, purpose)
- 同tick处理顺序固定
- 金标测试: 同seed跑100次，事件流逐条一致

### 6.6 Hot-Update Priorities

- 配置表（数值调整最频繁）
- 技能 Cell 参数（改参数不改代码）
- 战斗逻辑（需谨慎，影响确定性）

## 7. Scope

### 7.1 MVP Features

- 4 人在线对局（可先单机 4 AI 验证）
- 完整回合状态机（5 阶段循环）
- 经济系统（圣水收入/消耗）
- 商店 + 共享卡池（预扣机制）
- 24 单位 + 合成升星（2合1，最高4★）
- 13 羁绊（2/4 阈值）
- 技能系统（Cell 流水线，16 个 SkillDef）
- 确定性战斗模拟器 + 事件流
- 回合结算（扣血/配对/淘汰/Ghost）
- 基础 UI（部署/战斗/结算）
- 1 位统帅（皇室国王）

### 7.2 Phase 2 Features

- 断线重连
- 更多统帅（不同被动）
- 赛季/天梯排位
- 数据统计/战绩回顾
- 战斗回放功能
- 平衡性调优工具

### 7.3 Nice-to-Have

- 观战模式
- 好友系统/组队
- 成就/收集系统
- 自定义棋盘皮肤

### 7.4 Explicitly Out of Scope

- 实时操作（保持自走棋核心）
- PvE 关卡模式
- 付费影响数值（P2W）
- 单位自定义外观（MVP）
